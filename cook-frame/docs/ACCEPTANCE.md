# 验收用例（10 项）

被测应用：`iris.example.cookframe`（源码内 `APP_VER` = `v68`）
环境：IrisView Developer Kit v1.0.0 · 640×480 抬头视口 · 模拟器文本输入 + 麦克风
口径：**界面**以模拟器实际渲染为准；**状态**以画面左上角徽章 `[待命]/[处理中]/[待确认]/[完成]/[异常]` 为观察点；**证据**优先引用日志行（`/tmp/cook-mic.log`，同屏也有 `COOK_PAINT` 快照）。

> 自动化可复跑的部分：`node tools/test-ink.js`（字号/墨色 187 项）、`node tools/test-taste.js`（忌口记忆 80 项）、`node tools/test-boot.js`（点阵纯逻辑 20 项）、`node tools/mock-boot.js`（覆盖 1、2、3、5、7、9、10 + 开机点阵组 + 忌口记忆组）、`COOK_MOCK_LLM=1 node tools/mock-boot.js`（覆盖 5 的生成链路）。4、6、8 需要真机麦克风/断服务，人工执行。

## 用例 1 · 待命（开机点阵）→ 菜单 → 处理中 → 跟做（文本通道起步）

| 项 | 内容 |
|---|---|
| 前置 | 冷启动，无 `custom-dishes.json` |
| 操作 | ① 冷启动后先不输入，等 3 秒；② 键盘输入 `开始`；③ 键盘输入 `番茄炒蛋` |
| 期望 | ① 开机页：左上角 `[待命]`、点阵 21×9 在动（气泡从底往上浮）、主区「说「开始」/「走起」/「开工」都行」；② 说/打 `开始` → 进菜单「今天做什么菜？」+ 滚动列表（8 道一屏，右侧 `约 N 分`），点阵已收起；③ 提交 `番茄炒蛋` 瞬间 `[处理中]`（选菜动画 0.9 秒），结束变 `[跟做]`，主区「第 1 步」，右上角 `输入 · 文本`；④ 底栏给出下一步能说的话 |
| 证据 | `COOK_BOOT_DOT start grid=21x9`、`COOK_BOOT_ANIM f=11 …`、`COOK_BOOT_DOT hide`、`COOK_BOOT_START via=start-word`、`COOK_PAINT mode=menu … timer="当前 1. … 约 8 分"`、`COOK_STATE 待命 -> 处理中`、`COOK_LAYOUT normal`、`COOK_STATE 处理中 -> 跟做`、`COOK_PAINT mode=cooking …` |
| 不通过 | 出现 `undefined`/`NaN`；点阵压在菜名上；不输 `开始` 也能进菜单；状态徽章不切换；主步骤与步骤号不一致 |

## 用例 2 · 内容修改 + 重点/布局修改（两次连续调整）

| 项 | 内容 |
|---|---|
| 前置 | 已进入番茄炒蛋第 1 步 |
| 操作 | 依次说/打 `大字` → `精简` → `恢复` |
| 期望 | ① `大字`：主步骤字号 30→38，位置随之上移，内容不变；② `精简`：字幕行、麦克风行、底栏全部撤掉，只剩「第几步 / 主步骤 / 倒计时」；③ `恢复`：回到常规布局；④ 三次重排都不出现截断或叠字 |
| 证据 | `COOK_LAYOUT_CMD big/slim/normal`、`COOK_LAYOUT big/slim/normal`、三次 `COOK_PAINT`（`partial=""` 出现在精简态） |
| 不通过 | 只改了提示文字而布局没动；字号变了但文字溢出/被裁 |

## 用例 3 · 语音完成同一任务（模态一）

| 项 | 内容 |
|---|---|
| 前置 | 麦克风已授权，识别服务在线 |
| 操作 | 说 `下一步` |
| 期望 | ① 右上角 `输入 · 语音`；② 步骤从 1 前进到 2，界面文字与用例 2 的文本通道结果**一致**；③ 我刚说的那句 `🗣 下一步` 保留 8 秒后自动收走 |
| 证据 | `COOK_HANDLE final="下一步"`、`COOK_STREAM final … 8xx ms`、`COOK_PAINT mode=cooking …` |
| 不通过 | 语音与文本结果分叉；通道标签不更新；空草稿把整句冲掉 |

## 用例 4 · 文本完成同一任务 + 输入方式切换（模态二 + 切换）

| 项 | 内容 |
|---|---|
| 前置 | 上一句用语音说完 `下一步`，处在第 2 步；当前菜为「拍黄瓜」（该步带 5 分钟计时） |
| 操作 | 键盘输入 `开始计时` |
| 期望 | ① 右上角切回 `输入 · 文本`；② 倒计时行显示 `⏱ 5:00` 并逐秒递减；③ 说/打 `下一步` 仍能推进，计时随步骤重置 |
| 证据 | `COOK_TEXT "开始计时"`、`COOK_PAINT … timer="⏱ 5:00 …"`、`输入 · 文本` |
| 不通过 | 计时被重置或格式不是 `m:ss`；切换通道后状态徽章错乱 |

## 用例 5 · 待确认：生成菜必须先确认才执行

| 项 | 内容 |
|---|---|
| 前置 | 已配置模型，停在菜单页 |
| 操作 | 说 `我想吃酸辣土豆丝` |
| 期望 | ① `[处理中]`（先纠正、再生成）；② 生成成功 → `[待确认]`，主区「「酸辣土豆丝」已生成 · 要开做吗？」，菜单里这道带「（新）」；③ 说 `不用` → 回到 `[待命]`，菜留在菜单里但不开做；④ 再说 `开做` → 才进入做菜页 |
| 证据 | `COOK_LLM ask/ok`、`COOK_STATE 待命 -> 待确认`、`COOK_AI_DISH drop/confirm` |
| 不通过 | 生成后直接开做；未确认就写进收藏；确认后没有进入第 1 步 |

## 用例 6 · 独立纠正 + 上下文保持

| 项 | 内容 |
|---|---|
| 前置 | 番茄炒蛋第 1 步 |
| 操作 A | 说 `太咸了` |
| 操作 B | 接着说 `加两勺生抽` |
| 期望 | ① A：主步骤一个字不动，下方出补救建议（橙色），留到下一次回答；② B：同一步上直接改成「已改为：2 勺」，且不丢 A 的上下文；③ 说 `没听清，再说一遍` 只重念当前内容，不改任何量 |
| 证据 | `COOK_REPLY rescue …`、`COOK_PAINT … sub="💬 …"`、`COOK_PAINT … main="已改为：2 勺"` |
| 不通过 | 纠正把主步骤整段换掉；答案只闪一帧；旧答案覆盖新答案 |

## 用例 7 · 完成态与收尾

| 项 | 内容 |
|---|---|
| 前置 | 任一道菜走到最后一步 |
| 操作 | 说 `完成了` → `不用`（不存）→ `不用`（不做下一道） |
| 期望 | ① 第一步后 `[待确认]`，问「还想做下一道菜吗？」（内置菜不问收藏）；② 第二步后 `[完成]`，收工总页显示「今天做了 N 道菜」与每道用时；③ 在收工页说 `再做一道` 回菜单，状态回 `[待命]` |
| 证据 | `COOK_WRAP start/summary`、`COOK_STATE 跟做 -> 待确认`、`COOK_STATE 待确认 -> 完成` |
| 不通过 | 越界崩溃；收工页与「再做一道」互相抢；旧菜名留在新菜界面 |

## 用例 8 · 异常与降级

| 项 | 内容 |
|---|---|
| 前置 | 停掉本机 `asr_server.py`（模拟"服务失败"，属注入测试） |
| 操作 A | 说 `下一步` |
| 操作 B | 键盘输入 `下一步` |
| 期望 | ① A：`[异常]`（红），底栏/麦克风行写「识别服务没连上 · 先启动 asr_server.py（5001）」，**应用不退出、当前步骤不丢**；② B：文字通道照常推进，状态回到 `[跟做]`；③ 再恢复服务，5 秒内探活自动回到正常并提示「识别服务已连上」 |
| 证据 | `COOK_STATE 跟做 -> 异常`、`COOK_PAINT … mic="⚠ 识别服务没连上…"`、`COOK_TEXT "下一步"`、探活恢复日志 |
| 不通过 | 语音失败连带文字不可用；应用退出/重启；把服务故障说成"没听清" |

## 用例 9 · 可读性：字号舒适档 + 深浅层次

| 项 | 内容 |
|---|---|
| 前置 | 番茄炒蛋第 1 步（跟做页），主步骤 30 号字 |
| 操作 A | 说 `看不清`，再说一遍 `看不清`，最后说 `字小一点` |
| 操作 B | 说 `显示重点`，观察主步骤与底栏的亮度差 |
| 期望 | ① `看不清`：底栏 / 麦克风行 / 状态徽章 / 输入通道 14→16、顶部进度行 15→17；**主步骤仍 30、菜名仍 20**（不压行、不裁字）；② 再说一遍：回「已经是舒适字号了 · 嫌小再说「大字」」，不静默；③ `字小一点`：14/15 回来；④ 整屏层次固定：主步骤最亮（11:1）> 对话答案/倒计时（8.2:1）> 进度/时间列/状态（6.2:1）> 麦克风/底栏（4.5:1），**最暗一档也不低于 WCAG AA 的 4.5:1**；⑤ `显示重点` 时主步骤提到 13.3:1，比底栏更亮一档 |
| 证据 | `COOK_FONT boost=2 meta=16 progress=17 row=20 main=30`、`COOK_FONT_CMD comfort changed=true/false`、`COOK_FONT boost=0 meta=14 progress=15`；`node tools/test-ink.js` 逐档打印的对比度（4.5/6.2/8.2/11.0/13.3 : 1） |
| 不通过 | 小字放大后压行/被裁半截；舒适档把菜名或主步骤一起放大导致菜单 8 行挤在一起；任一档文字对比度 < 4.5:1（等于"看不清"）；连说两遍无反馈 |

## 用例 10 · 忌口 / 喜好的记忆（附加能力）

| 项 | 内容 |
|---|---|
| 前置 | 菜单页，之前没记过忌口 |
| 操作 A | 说 `我不吃葱`，再说 `我有什么忌口`，再说 `别放葱`（反例） |
| 操作 B | 说 `爱吃辣` → 说 `推荐`（看推荐语里是否带"你爱吃辣"） |
| 操作 C | 选「蛋炒饭」→ 连说三次 `下一步`（到第 4 步「撒葱花」）；最后说 `忘掉葱` 回菜单 |
| 期望 | ① `我不吃葱` 后：菜单里含葱的菜名后出现 `（含葱）`（蛋炒饭/紫菜蛋花汤/西红柿鸡蛋面/清蒸鲈鱼/麻婆豆腐），并写进 `taste.json`；② 查询回「🧠 我记得：不吃葱」；③ `别放葱` **不被记住**（这是这一锅的做法，不是一辈子）；④ 第 1-3 步底栏不提忌口，第 4 步底栏出现「⚠ 这步有葱（你忌口）· 不想放就说「跳过」」；⑤ `忘掉葱` 后菜单后缀全部撤干净，重启也不再标 |
| 证据 | `COOK_TASTE add kind=avoid added=["葱"] saved=true`、`COOK_TASTE step=4 hit=葱`、`COOK_TASTE remove ... removed=["葱"]`；`node tools/test-taste.js` 80 项（含 28 条反例） |
| 不通过 | 把 `别放葱 / 不放盐 / 火大一点` 记成长期忌口；菜名后缀被截成「（含香…」；档案改了界面没跟着撤；跨开机丢失 |
