# 开发手册

接手这个项目之前，建议先把这一页看完。这里的每一条都来自实际踩过的坑。

## 一、分层别搞混

```
麦克风 PCM → 本机识别服务(端口 5001) → 文字 → engine.js 理解 → 界面
```

识别服务只负责「声音变文字」，**不负责理解**。「下一步 / 太咸了 / 多大火」这些判断全在 `cook-frame/src/engine.js` 里。

改词、改说法，多数时候改的是 `engine.js` 和 `extra_vocab.txt`，不是识别服务。

## 二、开跑前确认三件事

Ubuntu（WSL 也行）里执行：

```bash
irisview --version                        # 工具包装好了吗
python3 --version                         # 3.10 以上
ls asr-service/vosk-model-small-cn-0.22   # 模型在不在（66MB，包里没带）
```

三个都正常再往下。模型去 `alphacephei.com/vosk/models` 下 `vosk-model-small-cn-0.22`，解压到 `asr-service/` 目录下。

## 三、跑起来：三步、两个终端

**终端 1**（这个窗口别关）

```bash
cd asr-service
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 asr_server.py
```

看到 `Running on http://0.0.0.0:5001` 就成功。验证（一定是 `/ping`，不是 `/health`）：

```bash
curl http://127.0.0.1:5001/ping
# {"ok":true,"model":"vosk-model-small-cn-0.22"}
```

**终端 2**

```bash
cd cook-frame
# ★ 第一步先改 FusionUIApp.json 里的 versionCode，改成比本机已有包更大的数字（比如 100）
irisview build .
irisview package . --output ../cook-frame.fuiapp --debug-unsigned
irisview run ../cook-frame.fuiapp --allow-debug-unsigned --display-mode mono
```

界面左上角应显示 v58c。不是 v58c 说明跑的是旧包。

## 四、八条坑，先看一遍

**1. versionCode 不升，改了也白改**

平台发现「内容变了但版本没升」会直接复用旧包。症状：代码改了，界面一点变化都没有，还以为是改错了地方。

**2. `irisview run` 必须带 `.fuiapp` 路径**

漏了不会报错，但打开的是默认客户端，不是我们的应用。三个命令的正确姿势：

| 命令 | 必须带 |
|---|---|
| `irisview build` | `.` |
| `irisview package` | `--output 文件名.fuiapp` |
| `irisview run` | `xxx.fuiapp` 路径 |

**3. build 完必须 package，package 完才 run**

只改源码然后 run，跑的还是上一次的包。

**4. 麦克风每次会话都要手动点一下确认**

平台限制，绕不过去：每次 `requestVoiceInput` 都要客户端确认，单次最长 60 秒。所以我们的做法是「一次授权连说多句」。

**5. 说话没反应，先查服务，不要先怀疑代码**

```bash
curl http://127.0.0.1:5001/ping
```

服务没起 / 端口不是 5001，界面看起来就是「有麦克风但不干活」。

**6. 词表不是越多越好，加多了反而更差**

`asr-service/extra_vocab.txt` 是重点词表，改完立刻生效（不用重启）。但 Vosk 小模型词表一大，就会在近音词之间乱选。

真实案例：「一共几步」被拼成「收工油几步」，因为「收工」「几步」都是词表里的词，它们互相抢。所以一次加 3–5 个，说完看日志，不行就删掉那几行。

**7. 判断「是没听清还是没听懂」，看日志**

```bash
tail -50 /tmp/cook-mic.log
```

```
COOK_STREAM final "下一步"      ← 听清了，文字是这个
COOK_HANDLE final="下一步"      ← 文字进到界面处理了
COOK_PAINT mode=cooking ...     ← 界面上实际画的字
```

有第一行没第二行 = 回调断了；有第二行没第三行 = 显示被覆盖了。

**8. 界面文字位置别乱调**

640×480 的固定坐标，几行是紧挨着的：

| y 坐标 | 内容 |
|---|---|
| 26 | 进度 |
| 64 | 提示 |
| 92 | 识别文字 |
| 120 | 主内容 |
| 330 | 副标题 |
| 404 | 麦克风状态 |
| 448 | 底部提示 |

改动前先看它会不会压到相邻那行（之前就发生过识别文字压住副标题，看起来像「根本没显示文字」）。

## 五、改代码之前，先知道各文件管什么

| 文件 | 职责 | 改坏的后果 |
|---|---|---|
| `cook-frame/src/voice.js` | 收音、静音判断、切句 | 听不见 |
| `cook-frame/src/asr.js` | 跟识别服务的 HTTP 接口 | 连不上 |
| `cook-frame/src/engine.js` | 听懂人话（翻页/救场/改量/提问），纯逻辑好测 | 口令失灵 |
| `cook-frame/src/index.js` | 界面、菜单、口令分发 | 界面空白 |
| `cook-frame/src/recipe.js` | 11 道菜的菜谱数据 | 菜品缺失 |
| `asr-service/extra_vocab.txt` | 识别重点词（改完不用重启） | 近音词乱选 |
| `asr-service/asr_server.py` | 识别服务本体（改完要重启 python） | 服务起不来 |

改 `engine.js` 或词表之后，跑这个（58 条核心口令，必须全过）：

```bash
cd cook-frame
node tools/test-engine.js
```

挂了就说明核心口令被改坏，先修它再打包，别往下走。

## 六、跑起来后，用这几句验一遍

- 菜单页：「下一页」「番茄炒蛋」「推荐」
- 跟做中：「下一步」「上一步」「多大火」「一共几步」
- 故障类：「太咸了」「糊了」「油冒烟了」
- 其他：「换菜」「再说一遍」「开始计时」

都能正确回应，说明链路是通的。

## 七、两个别动的地方

1. **别把识别服务换成需要联网的方案。** 比赛现场可能没网，现在是纯本机（Vosk + 端口 5001），断网也能跑。
2. **别整体替换 `engine.js`。** 现在这套的 58 条核心口令全过，换规则之前先跑 `node tools/test-engine.js` 和 `node tools/eval-corpus.js` 对比，别凭感觉换。

## 八、提交代码时注意

仓库里不包含这些东西，别手动加回来：

- `config.json`（含 API 密钥，只提交 `config.example.json`）
- `vosk-model-*/`（66MB 模型）
- `node_modules/`、`.venv/`、`*.fuiapp`、`*.log`
